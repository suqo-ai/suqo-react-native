# Changelog

All notable changes to `@suqo/react-native` are documented here. Entries from 0.0.2 on are
generated by semantic-release from conventional commits and land through the release PR; see
RELEASING.md.

## [0.0.1](https://github.com/suqo-ai/suqo-react-native/releases/tag/v0.0.1) - 2026-10-07

The first published version. Earlier `0.1.0` and `0.2.0` changelog entries described versions that
were never published; what they added is folded in below.

### Features

- `SuqoProvider` and `useSuqoCheckout()`. One provider at the app root owns a single full-screen
  checkout screen; `open({ sessionId })` shows it and reports the outcome through exactly one of
  `onSuccess`, `onFailure` or `onClose`. It also resolves a promise, so `await` works instead of
  callbacks. `close()` dismisses it. The checkout session is created on your backend and must
  already carry the buyer; nothing about the buyer passes through this SDK.
- `mode` prop on `SuqoProvider`: `'live'` resolves to `app.suqo.ai`, `'sandbox'` (the default) to
  `test.suqo.ai`. `baseUrl` is optional and overrides it when set. `LIVE_ORIGIN`,
  `SANDBOX_ORIGIN`, `resolveBaseUrl` and the `CheckoutMode` type are exported alongside
  `DEFAULT_CHECKOUT_PATH` (`'/c/:id'`).
- A `suqo:unavailable` event carrying `not-found | expired | spent | no-customer | no-methods |
load-failed`. Deliberately an event and not a callback: no payment was attempted, so `onFailure`
  would be a lie. The buyer sees the page's own explanation and dismisses, which settles as
  `closed`.
- The screen is built from React Native core primitives — `Modal` and `Animated` — so
  `react-native-webview` is the only native dependency and the package works in Expo Go with no
  configuration. Presented as a full-screen modal rather than a route, so it needs no navigation
  library and no route registration, and Android's hardware back button dismisses it like any
  screen.
- The checkout block scrolls inside the screen, which a seller with NPS enabled needs: the bank
  list alone runs to about 1500px.
- `loadingLabel` on `SuqoProvider` — the line under the large spinner while the page loads.
  Defaults to `Loading secure checkout`; pass `''` for a spinner on its own. The loading state
  covers the whole page it is loading.
- Bank and wallet deeplinks (`fonepayApp://`, Android `intent://`) are lifted out of the WebView
  to `Linking.openURL`, which a WebView cannot resolve itself. `javascript:`, `data:`, `file:` and
  `blob:` navigations are refused outright. `suqo:intent` (the browser SDK's deeplink message) is
  dropped on purpose: this WebView already navigates to a deeplink in the same window and lifts it
  through navigation interception.
- Gateway return pages are allowed to load, because that is where the payment is verified. The
  outcome is taken from the page's own `suqo:result` message, after verification.
- Two load deadlines (12s to first signal, 25s to the block mounting) with a retry, so a page that
  never boots reports a loading failure rather than hanging.
- `debug` forwards the page's own console output, errors and requests to the host's console, with
  redaction; session ids are redacted by shape as well as by key. An `onEvent` stream feeds the
  host's own logs.
- `VERSION`, this package's version as published.
- `docs/usage.md` — an integrator-facing guide covering the full `onEvent` surface, the options
  table, and troubleshooting by error-panel copy.

### Requires

- The SUQO web app must serve `/c/<sessionId>`, route `postToHost` and `publishResult` through
  `window.ReactNativeWebView`, treat an RN host as a gateway window, and hand off to gateways in
  the same window. Without those, the checkout page loads but reports nothing.
